# AI Policy

AI assistance is allowed. You remain responsible for everything you submit, including code, tests, documentation, and reports.

## Review and verification

- Read the full diff and understand how the change fits into mdv. Be prepared to explain your decisions during review.
- Check suggested APIs, CLI flags, and references against the implementation or primary documentation.
- Run the applicable checks in [CONTRIBUTING.md](CONTRIBUTING.md#checking-your-work). Report only checks you actually ran and explain any you skipped.
- For code fixes, add or update a test that catches the bug. Check that the assertion covers the intended behavior.
- Remove unrelated edits, unused helpers, and generated boilerplate before submitting.

For documentation and translations, check facts and examples and edit the wording yourself.

## Disclosure

If AI generated or substantially rewrote code, tests, documentation, or technical explanations, disclose that assistance in the PR or issue description. Include:

- The tool or model used, if known.
- Which parts it helped produce.
- How you reviewed and verified the result.

A short note is enough; chat transcripts are not required. Minor autocomplete suggestions and spelling corrections do not need a separate note.

## Issues and review replies

For bug reports, include what you observed and how to reproduce it. Mark suspected causes as hypotheses. Feature requests should describe your use case and the proposed behavior.

Read and verify AI-assisted descriptions and review replies before posting them. Address the actual question or feedback.

The maintainer may request changes or close a contribution that lacks human review, contains unsupported claims, or cannot be explained by its author.
